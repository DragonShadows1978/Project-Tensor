## Findings

| ID | Severity | Location | Argument and fix |
|---|---|---|---|
| BWDREV4AX-F01 | MINOR | `tensor_cuda/tensor_cuda/__init__.py:1458`, `:1469–1486` | The docstring describes no-grad forward and guarding as unconditional. The native shortcut calls `fn` once in the incoming mode if grad mode is off or no explicit input requires grad, including an empty list. The CPU shortcut cases accepted marked writes and the zero-argument call could return an ordinary differentiable graph. Clarify when checkpointing and guarding activate, that guarding is per storage, and that an external write needs `mark_modified()` on the checkpoint input or an alias sharing its actual Storage. State that callers must keep replay-relevant state stable, including `requires_grad` flags. |
| BWDREV4AX-F02 | MINOR | `tensor_cuda/src/bindings.cpp:200` | An invalid replay return fails the cast after grad mode has been forced on. With backward called inside `tc.no_grad()`, both `None` and a dict left grad mode enabled inside that context after the exception was caught. This path predates the diff and concerns a callback that violates the documented return type. Move the cast into the guarded replay region, so conversion and backward restore the incoming mode on every exit. |
| BWDREV4AX-F03 | MINOR | `tc_signal/tests/test_bwd_r4_norm_affine.py:21`, `:154` | All new nondegenerate numerical cases train `x`. The older frozen-`x`, scale-only case has `T=1` and expects zero dscale. A regression that returns zero dscale specifically when `needs_x` is false would pass these tests. Run the N=2, T=7 scale-only case with frozen `x` too. Check its nonzero dscale against the existing fp64 oracle and require `x.grad is None`. |
| BWDREV4AX-F04 | NIT | `tensor_cuda/tensor_cuda/__init__.py:1466` | “PyTorch’s reentrant checkpoint has the same contract” conflates saved input slots with the requirement to explicitly pass every tensor read. PyTorch's own reentrant `checkpoint_sequential` closes over modules and passes only the activation. Qualify the comparison to saving and version checking explicit inputs. |

Evidence for F01 and F02 is the CPU boundary probe and the parent/current source comparison. F03 combines source reasoning with the shipped CPU oracle. On the N=2, T=7 scale-only fixture, setting dscale to zero gives error-to-bound ratios of 5,732, 12,155 and 8,462. F04 is inspection of installed PyTorch 2.11.0 source, without importing PyTorch. ## Checkpoint behavior

| Case | Ruling and evidence |
|---|---|
| Snapshot and post-forward comparison | Native lines 153–170 take the snapshot before user code, then check each slot after `NoGradGuard` restores the incoming mode. The candidate refuses the marked write even through a view and even if the result is also malformed. The one write already made remains visible. The corresponding shipped test fails on r5m03. |
| Backward comparison | Native lines 174–186 test every explicit slot, including frozen slots, before replay input construction, grad-mode change or `fn` invocation. A marked change to an active or frozen input, or a revision bump alone, is refused. Calls remain forward-only and neither leaf gets a checkpoint contribution. r5m01 misses all three cases. |
| Shared storage and views | A copied `NDArray` handle preserves its storage, shape and offset. Two distinct leaves sharing one unchanged allocation both received the exact expected gradient in the boundary probe. An unchanged reshape view propagated the exact gradient to its base. Writing through an alias bumped both saved slots, and the error named the first slot, 0, with no replay. Duplicate slots use the same revision and their gradient contributions are accumulated per argument. The numerical duplicate-Variable accumulation path was assessed from source. |
| Empty, all-frozen and no-grad inputs | Zero explicit slots take the direct-call path. All-frozen calls preserve the caller's grad mode, and no-grad calls run with it disabled. Both bypass revision tracking because there is no checkpoint replay. |
| Non-tensor outputs | A dict returned by the initial forward is rejected by the native Tensor cast in both paths, with the incoming grad mode preserved. The binding errors for invalid replay outputs differ by object type. Both fail the cast, yielding F02. |
| Error text | Zero-based slot indices identify the first mismatch. The CPU probe verified `checkpoint: fn modified input slot 0 in place; a checkpointed function must not write its inputs` and `checkpoint: saved input slot 0 was modified after the checkpointed forward` verbatim. A callback that throws instead of returning propagates its own exception through the forward guard. |
| Wrong gradients and refusals | The CPU probes found no wrong gradient or unsupported refusal for replay-equivalent calls with unchanged guarded inputs. Revision changes can conservatively refuse a call even if the bytes are unchanged, as the mark-only test requires. The documented closure case replayed the changed value and returned `[40,-5,6]`. Changing a frozen explicit operand to trainable after forward leaves its Storage revision unchanged. The same pure product then gave it an extra gradient of `[1,2,3]` under checkpointing and no gradient under plain `attach_vjp`. This pre-existing metadata behavior is outside the Storage counter and motivates the contract clarification in F01. |

The Python wrapper forwards the positional inputs in order via `_C.checkpoint(fn, list(inputs))`. The tracked-path wording and both revision errors match native behavior. The known bypasses operate on writes without a bump on the **original saved Storage**. A DLPack re-import can have the same data pointer and a different Storage counter. ## Prior art

- Chen et al. (2016), *Training Deep Nets with Sublinear Memory Cost*, for activation recomputation. PyTorch autograd (Paszke et al., 2019) supplies saved-tensor version counters. TensorCUDA adds checks around the forward and before replay on explicit Storage revisions. The boundary probes are this review's cases. No prior art known to me for the exact TensorCUDA-specific probe set.
- Stroustrup (1994), C++ resource lifetime and scope-based cleanup, for restoring state when an exception leaves a scope. F02 applies the existing grad-mode cleanup pattern to the result cast.
- Ulyanov, Vedaldi and Lempitsky (2016), instance normalization, and Ioffe and Szegedy (2015), the normalization affine chain rule. F03 reuses the shipped fp64 fixture and adds a frozen activation to the proposed test.
- DeMillo, Lipton and Sayward (1978), mutation analysis. The order supplies both mutants. This review independently counts their per-test effects.
