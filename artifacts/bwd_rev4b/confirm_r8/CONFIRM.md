## Blocking findings

### BWDR4BR8-F01 · MAJOR

**Generic receipt verification rejects every passing staged launch.** All eight commands in the staged list reach the r8 worker and return through the r8 launcher. The worker always writes `VOICE_MTIMES_R4B_R8.json` through `VoiceReads.finish`, whose JSON has `before`, `after`, `changed`, and `write_attempts`. The staging launcher digests every file. The documented `verify-receipt` passes all those names to `verify_launch`, which requires `launch_id` in every JSON. The inherited G1/G2 and MFCC sign-mutant writers and the NVML sampler also omit the field. [Staged commands](../../../../tensor_fork_bwd_wt_r4b/artifacts/bwd_r4b/STAGED_LINES_R4B_R8.md#L30) · [Worker census call](../../../../tensor_fork_bwd_wt_r4b/scripts/bwd_r4b_stage_r8.py#L273) · [Census writer](../../../../tensor_fork_bwd_wt_r4b/scripts/bwd_r4_gate.py#L172) · [G1 and sign-mutant writers](../../../../tensor_fork_bwd_wt_r4b/scripts/bwd_r4b_gpu_r6.py#L270) · [Sampler writer](../../../../tensor_fork_bwd_wt_r4b/scripts/bwd_r4b_nvml_sampler_r6.py#L118) · [Generic verifier](../../../../tensor_fork_bwd_wt_r4b/scripts/bwd_r4b_stage_r8.py#L233) · [Read rule](../../../../tensor_fork_bwd_wt_r4b/scripts/bwd_r4b_gpu_r8.py#L320)

On the retained lead bytes, all eight launcher logs and worker-file maps matched their recorded hashes. The generic verifier then refused each one with `carries another launch identity`. The first file refused was a G1/G2 or MFCC sign-mutant verdict on three lines, NVML JSON on two, and Voice census JSON on three. The narrower G-API baseline check correctly succeeds on its two required files. Define the per-line primary result and auxiliary file contracts. Have each primary writer emit the launch ID and require it. Bind auxiliary files with the launch receipt's hashes and check their own schemas, including the sampler’s existing header schema. Exercise generic verification on the eight retained receipt shapes. [CPU probes](commands/21-cpu-probes.out)

### BWDR4BR8-F02 · MAJOR

**A partial reference census leaves a failed command eligible for MFCC.** The staged merge calls the r8 wrapper, which writes a passing END after the mode body. The inherited CLI then writes the census in its outer `finally`. That writer opens the final name in create-only mode before dumping JSON and can raise from the write. The r8 root check tests the expected census filename only. Ref-at-wave bundle verification has no census digest or schema check. Both staged MFCC launch paths use these checks. [Staged merge](../../../../tensor_fork_bwd_wt_r4b/artifacts/bwd_r4b/STAGED_LINES_R4B_R8.md#L55) · [END writer](../../../../tensor_fork_bwd_wt_r4b/scripts/bwd_r4b_refwave_r8.py#L91) · [CLI finalization](../../../../tensor_fork_bwd_wt_r4b/scripts/bwd_r4b_refwave.py#L308) · [Create-only writer](../../../../tensor_fork_bwd_wt_r4b/scripts/bwd_r4_gate.py#L71) · [Root check](../../../../tensor_fork_bwd_wt_r4b/scripts/bwd_r4b_verify.py#L530) · [MFCC preflight](../../../../tensor_fork_bwd_wt_r4b/scripts/bwd_r4b_stage_r8.py#L209)

On a copy of the passing lead root, the real `VoiceReads.finish` hit `OSError: [Errno 27] File too large` under a 128-byte file-size limit. Its file existed but the strict reader rejected it with `Expecting value: line 6 column 4 (char 128)`. The exact root and bundle functions used by preflight both accepted. The manifest was still `634bf770d0ea38ee76ae02d621780f26f3ab9ac9f0bf8e4ed2ca4227527e8b49`. Publish a passing END only after the census write and validation succeed. Bind the completed census to the END and have the consumer strictly read it and verify the digest and clean census result. Keep the independent manifest bytes unchanged.
