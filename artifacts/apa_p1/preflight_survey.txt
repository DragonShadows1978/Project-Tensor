### TQ4 codes and row stride

Logical coordinates are `[B,KVH,C,D/2]` uint8 codes plus `[B,KVH,C]` fp32 norms, where C is capacity (distinct from the kernel chunk constant also named C=256) and S≤C is visible length. Byte `pair` packs coordinate `2*pair` in its low nibble and `2*pair+1` in its high nibble; threshold equality goes to the lower centroid (`x > boundary`, not ≥). Norm/rotation preparation uses a fixed per-row operation order independent of append shape (tensor_cuda/src/apa_spo/packed.cuh:15-40). Rotations `[KVH,D,D]`, codebook[16] and boundaries[15] are shared, non-token state (tensor_cuda/tensor_cuda/__init__.py:1321-1329).

For flattened head `bh=b*KVH+h`, code byte address is `((bh*C+j)*(D/2)+pair)`; norm address is `bh*C+j`. Thus token pitch is **64 bytes**, head-row pitch is **C*64 bytes**, and norm token/head pitches are **4 / C*4 bytes** at D128. This is not an arbitrary stride vector: a capacity parameter derived from codes.shape[2] supplies the pitch. Both main bulk kernels already distinguish visible S from code capacity (tensor_cuda/src/apa_spo/eb3.cuh:264-275,795-818; tensor_cuda/src/apa_spo/eb4.cuh:139-152,723-745). `apa_spq1_buffer_check` explicitly accepts codes capacity ≥ K visible length (tensor_cuda/src/apa_spo/packed_launcher.cuh:8-12).

### Existing precedent

Packed codes already accept **capacity ≥ visible S** and address `bh*capacity+j`, whereas K/V use `bh*S+j`. Token vectors remain compact in both formats. Code token/head-row pitches are D/2 / C*D/2 bytes; norms 4 / C*4 bytes. Evidence: tensor_cuda/src/apa_spo/packed_launcher.cuh:8-12; tensor_cuda/src/apa_spo/eb3.cuh:264-275; tensor_cuda/src/apa_spo/eb4.cuh:139-152. This is the model for the new ABI, without requiring arbitrary global NDArray stride support or changing production DLPack's contiguous-only contract.

### Minimal proposed ABI (reasoning; no implementation)

1. **Separate visibility from backing storage.** Add optional `visible_length` and **64-bit element pitches** `k_row_stride`, `v_row_stride`, plus `vi_row_stride` and `vs_row_stride` for tk8. Here a “row” is a flattened `(batch,KV head)` cache row, not a single token: `bh=b*KVH+kvh`, address `K[bh*k_row_stride+j*D+d]`, `V[bh*v_row_stride+j*VD+d]`, `VI[bh*vi_row_stride+j*VD+d]`, `VS[bh*vs_row_stride+j]`. Tensor storage is compact capacity-shaped `[B,KVH,C,D]` / `[B,KVH,C]`; its head pitch is C*D / C. Default S=K.shape[2] and compact pitches reproduce old calls. Support a compact capacity tensor first; do not reinterpret a metadata-only visible-shaped NDArray as if it had a larger legal storage extent. Bindings forward explicit S/pitches through `include/tc/ops.h` and EB3/4 host functions (existing sites: bindings.cpp:1034-1057; ops.h:331-340; eb3.cuh:737-768; eb4.cuh:664-694).
2. **Validate once on host.** Require 0<S≤each storage capacity, same B/KVH/device, correct dtypes, inner dimension contiguous and D=VD=128 for these EB entries, and workspace.valid_rows==S. Derive/check pitches against the capacity shape and storage extent; use checked 64-bit byte arithmetic including offset, final vector width and last head so oversized values cannot overflow into an in-bounds-looking pointer. Keep S≤65536 for EB4, and preserve group restrictions. Select masks, NB=ceil(S/64), NC=ceil(S/256), row carry, scratch and every launch bound use **S**, never capacity. Code capacity remains independently validated. Sites to replace are the host shape/equality checks in the census, not generic Tensor/DLPack ownership code.
3. **Change actual K/V addresses and every prefetch.** EB3 `select_pv` needs K and V pitches; `bulk_swap` needs V pitch for cross-kernel prefetch, and optional rotation V prefetch must iterate per-head visible ranges rather than a flat B*KVH*S range. Update optional KPF addresses too. EB4 `select_mixed`, `bulk_stats` prefetch and `prefetch_v` need V/VI/VS pitches; exact K gets its own pitch. Separate `voff`, `vioff`, `vsoff` instead of reusing one compact `tok/off`. No pitch enters merge arithmetic, query rotation math, bulk packed loads, score/flag layouts or reduction ordering. The existing kernel signatures/addresses are cited in the census. Variant-B cross-check needs matching host forwarding and pitches in `spq4::select_pv`; shared `eb2b::fetch_value8` needs the same independent V/VI/VS address split if exposed. Compact-only predecessor entries may retain their old contracts; do not route capacity arguments into them accidentally.
4. **Pack only new K rows in place.** Extend `ApaSpq1Workspace.append`/`packed_prepare`/`apa_spq1_prepare` and `spq1::prepare` with S, input head pitch and start=old valid_rows. Read `bh*k_row_stride+j*D`, j∈[oldS,S), keeping exactly the existing per-key norm and rotation operation sequence. `pack_tq` already has independent destination capacity and start; it can remain unchanged. Atomically at the host state level advance valid_rows only after successful enqueue on the same stream used by the consumer. Sites: __init__.py:1330-1343; bindings.cpp:1001-1003; packed_launcher.cuh:24-43; packed.cuh:15-40. Merely adding decode pitches and leaving `append(kp)` would retain the K prefix copy.
5. **Change SPLayer, not the model's source tensors.** Keep capacity allocations and torch in-place writes at scripts/apa_ab1_arms.py:274-301. For L=1, pass `self.Kt/self.Vt` directly with visible nk and their capacity pitches; call pitched workspace append; pass whole uint8 alias of `self.VIt` plus capacity-shaped `self.VSt` for tk8. Remove the per-step `.slice` uses at :304 and :317-319 from this branch. Keep quantizing **new** V rows at :300-301 (unchanged standalone quantizer), then copying those new code/scale rows to cache; do not re-quantize the prefix. Query staging at :320 is independent. Preserve cache owner references and the stream-order agreement in interop.py:3-6,22-48. The fp32 carrier can remain as a backing allocation; a full-capacity uint8 alias avoids all prefix-carrier copies and never converts int8 bytes via bf16.
6. **Prefill boundary.** For the smallest decode-only change, move the existing prefix copies inside L>1 and leave K1/reconstruction behavior unchanged. That removes all growing-cache prefix copies **per decode step**, with one-time/chunked prefill copies still present. If the implementation order instead demands zero prefix copy across prefill too, extend Python K1 with separate K/KQ/V pitches and visible S, relax its all-tensors-is_contiguous check only for the validated capacity-backed layout, and change `_k1` loads at apa_triton/k1.py:61-66. KQ reconstruction remains a temporary dense visible tensor and can keep its own compact pitch. AOT K1 is a separate optional integration; its wrapper currently fabricates contiguous strides (:147-159), although the AOT arguments already include strides. Do not bundle its redesign into the packed decode minimum.
7. **Optional production raw SP extension.** The packed port can leave the old dense SP APIs compact-only. A general pitched production SP API additionally needs a **kq pitch** (not just K and V): forward S/pitches through the two bindings and epsilon host forwarder, update `apa_selective_sp_splitk_dispatch/kernel` (and serial SP/diagnostics if those APIs expose pitches), retain the merge unchanged. Sources are S1 and the production rows in the census. This is additive ABI scope, not a packed-cache requirement.

**Alignment/vector constraints.** Preserve 16-byte-aligned K/V base pointers and head pitches divisible by 8 bf16 elements for the exact-K/PV uint4 loads; query uint2 loads need 8-byte alignment. TQ4 code bases/head pitches must remain 16-byte aligned for uint4 packed loads (D128 token pitch 64 bytes automatically satisfies this for integer capacities). Int8 `value8` uses an 8-byte uint2 read and bf16 conversion, so require vi base/head pitch multiple of8 bytes; scale base/head offset aligned to4 bytes. Token D=VD=128 makes K/V token pitch256 bytes and VI pitch128, so **capacity need not be a multiple of64/256**; visible tail masking stays necessary. Sources: eb3.cuh:256,272-275,374-388,424-435; eb4.cuh:149-152,399-411,450-466; eb2b_values.cuh:12-24. Explicitly validate these assumptions at the new boundary because vector reinterpret_casts themselves are not alignment checks. Reject unsupported layout/alignment with a clear error, before launching.

**Bitwise-preservation boundary (reasoning, not a new result).** On identical finite cached K/V and the same code/norm bytes, S, δ, fraction, carry, sinks and flags, the pitch changes only integer addresses. Preserve per-row pack arithmetic, all three hi/lo MMAs, exact-K union, P rounding, FP32 reduction chains and ascending-chunk merge order. Then the mathematical instruction/operand sequence within the **same EB3/EB4 arm** is unchanged; suffix/padding must not participate in statistics or softmax. Fused merge's arrival CTA may differ, but its reduction order is fixed (eb3.cuh:464-477). Preserve launch/tile configuration and verify emitted behavior in a later order, since source reasoning alone does not establish compiler-level bitwise identity. This is not a claim that packed SP is bitwise equal to production SP1.1, which uses different bulk math and partition-local carry. Future verification should compare compact vs capacity-backed output, packed bytes, masks/flags and append histories on identical captured rows, with poisoned unused suffixes and lengths crossing64/256 boundaries; no such run occurs here.
