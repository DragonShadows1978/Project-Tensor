13: - Indices are zero-based: the primer's "key 1" is key `0` here.
14: - `bulk` is a key's cheap (quantised) score, and `exact` its full-precision score.

25: /-- Running (prefix) maximum of `b` over keys `0..j`: the SP rule's `max(bulk[0..j])`. -/
26: def prefixMax {n : ℕ} (b : Fin (n+1) → ℝ) (j : Fin (n+1)) : ℝ :=
27:   (univ.filter (fun i : Fin (n+1) => i ≤ j)).sup' ⟨j, by simp⟩ b
28: 
29: /-- Maximum of `b` over the whole row. -/
30: def rowMax {n : ℕ} (b : Fin (n+1) → ℝ) : ℝ :=
31:   univ.sup' univ_nonempty b
32: 
33: /-- Prefix maximum of `b` restricted to one split-K partition `P` that contains key `j`. -/
34: def localPrefixMax {n : ℕ} (P : Finset (Fin (n+1))) (b : Fin (n+1) → ℝ) (j : Fin (n+1)) (hj : j ∈ P) : ℝ :=
35:   (P.filter (fun i => i ≤ j)).sup' ⟨j, by simp [hj]⟩ b
36: 
37: /-- The SP refine rule (primer §4.1, Q2): refine key `j` iff `bulk_j ≥ max(bulk[0..j]) − δ`. -/
38: def spRefined {n : ℕ} (bulk : Fin (n+1) → ℝ) (δ : ℝ) (j : Fin (n+1)) : Prop :=
39:   prefixMax bulk j - δ ≤ bulk j
40: 
41: /-- The final-maximum rule: refine key `j` iff `bulk_j ≥ max(bulk) − δ`. -/
42: def finalRefined {n : ℕ} (bulk : Fin (n+1) → ℝ) (δ : ℝ) (j : Fin (n+1)) : Prop :=
43:   rowMax bulk - δ ≤ bulk j
44: 
45: /-- The scores the online softmax sees: the exact score where a key is refined, the bulk score elsewhere. -/
46: def mixedScores {n : ℕ} (bulk exact : Fin (n+1) → ℝ) (refined : Fin (n+1) → Prop) : Fin (n+1) → ℝ :=
47:   fun i => if refined i then exact i else bulk i
48: 
49: /-- One row's attention output for scalar values `V`. Every key stays in the single softmax denominator. -/
50: def rowOutput {n : ℕ} (scores V : Fin (n+1) → ℝ) : ℝ :=
51:   (∑ i, Real.exp (scores i) * V i) / (∑ i, Real.exp (scores i))
52: 
53: /-- The two-pass kernel's z-score rule (production `apa_selective_kernel`, `tensor_cuda/src/kernels.cu`, at b4da646:
54: pass 1 accumulates `a = |bulk|` and `a*a`; `mean = total/cnt`; `var = total_sq/cnt − mean*mean`;
55: `thr = mean + zthr*sqrtf(fmaxf(var, 0))`; pass 2 refines iff `fabsf(bulk) >= thr`). Real arithmetic, no rounding. -/
56: def zRefined {n : ℕ} (b : Fin (n+1) → ℝ) (z : ℝ) (j : Fin (n+1)) : Prop :=
57:   let N : ℝ := n + 1
58:   let mean := (∑ i, |b i|) / N
59:   let var := (∑ i, |b i| ^ 2) / N - mean ^ 2
60:   mean + z * Real.sqrt (max var 0) ≤ |b j|
61: 
62: /-! ## 1. `sp_skip_final`: a skipped key stays skipped (primer §4.1, Q2: the SP rule is monotone, hence
63: exactly single-pass). A skip decided at key `j` is still a skip against every later prefix maximum, and against the
64: final maximum. -/
65: def sp_skip_final_stmt : Prop :=
66:   ∀ (n : ℕ) (b : Fin (n+1) → ℝ) (δ : ℝ) (j k : Fin (n+1)),
67:     ¬ spRefined b δ j → (j ≤ k → b j < prefixMax b k - δ) ∧ ¬ finalRefined b δ j
68: 
69: def sp_skip_final_nv_stmt : Prop :=
70:   ∃ (b : Fin (1+1) → ℝ) (δ : ℝ) (j : Fin (1+1)), ¬ spRefined b δ j
71: 
72: /-! ## 2. `sp_mask_superset`: the SP mask contains the final-maximum mask (primer §1 / §4.1: SP "replaced the
73: rule", and its mask is a superset of the final-max mask). The witness shows the containment can be strict. -/
74: def sp_mask_superset_stmt : Prop :=
75:   ∀ (n : ℕ) (b : Fin (n+1) → ℝ) (δ : ℝ) (j : Fin (n+1)),
76:     finalRefined b δ j → spRefined b δ j
77: 
78: def sp_mask_superset_nv_stmt : Prop :=
79:   ∃ (b : Fin (1+1) → ℝ) (δ : ℝ) (j : Fin (1+1)), spRefined b δ j ∧ ¬ finalRefined b δ j

81: /-! ## 3. `splitk_contains`: split-K selection contains the global SP rule, but output equality fails
82: (primer §4.2). A partition-local prefix maximum is never above the global one, so a key refined by the global
83: SP rule is refined in its partition. Counterexample: bulk [2,0], exact [2,10], V = [0,1], δ = 0. Global SP (one
84: partition) against split-K with partitions {0} and {1}: the outputs differ by more than 0.8. -/
85: def splitk_contains_stmt : Prop :=
86:   (∀ (n : ℕ) (P : Finset (Fin (n+1))) (b : Fin (n+1) → ℝ) (δ : ℝ) (j : Fin (n+1)) (hj : j ∈ P),
87:       localPrefixMax P b j hj ≤ prefixMax b j ∧
88:       (spRefined b δ j → localPrefixMax P b j hj - δ ≤ b j)) ∧
89:   (let bulk : Fin (1+1) → ℝ := ![2, 0]
90:    let exact : Fin (1+1) → ℝ := ![2, 10]
91:    let V : Fin (1+1) → ℝ := ![0, 1]
92:    let globalOut := rowOutput (mixedScores bulk exact (fun i => spRefined bulk 0 i)) V
93:    let splitOut := rowOutput
94:      (mixedScores bulk exact (fun i => localPrefixMax {i} bulk i (mem_singleton_self i) - 0 ≤ bulk i)) V
95:    (0.8 : ℝ) < |splitOut - globalOut|)
96: 
97: def splitk_contains_nv_stmt : Prop :=
98:   ∃ (b : Fin (1+1) → ℝ) (δ : ℝ) (P : Finset (Fin (1+1))) (j : Fin (1+1)), j ∈ P ∧ spRefined b δ j

100: /-! ## 4. `z_not_single_pass`: the z-score rule cannot run in one irrevocable pass (primer §4.1, Q1). The
101: rows [1,0,0,0] and [1,0,0,10] share the prefix [1], yet for every `z ∈ [0, √3]` key 0 is refined in the first and
102: not in the second. So no decision that sees only the prefix (here: key 0's bulk value) agrees with the rule on both
103: rows. -/

105:   ∀ z : ℝ, 0 ≤ z → z ≤ Real.sqrt 3 →

109:       ¬ ((f 1 ↔ zRefined (![1, 0, 0, 0] : Fin (3+1) → ℝ) z 0) ∧
110:          (f 1 ↔ zRefined (![1, 0, 0, 10] : Fin (3+1) → ℝ) z 0))

115: /-! ## 5. `sp2_certificate`: the SP2 δ certificate (primer §4.3). Suppose every key's bulk error is at most
116: `errq` (the primer's `e_q`). If the SP rule with `δ = ln(1/ε) + 2·errq` skips key `j`, then its true weight is
117: below `ε` times the true maximum's weight: `exp(exact_j) < ε · exp(max exact)`. This is the true-weight form. -/
118: def sp2_certificate_stmt : Prop :=
119:   ∀ (n : ℕ) (bulk exact : Fin (n+1) → ℝ) (errq ε : ℝ) (j : Fin (n+1)),
120:     0 < ε →
121:     (∀ i, |bulk i - exact i| ≤ errq) →
122:     ¬ spRefined bulk (Real.log (1 / ε) + 2 * errq) j →
123:     Real.exp (exact j) < ε * Real.exp (rowMax exact)
124:

126:   ∃ (bulk exact : Fin (1+1) → ℝ) (errq ε : ℝ) (j : Fin (1+1)),
127:     0 < ε ∧ (∀ i, |bulk i - exact i| ≤ errq) ∧ ¬ spRefined bulk (Real.log (1 / ε) + 2 * errq) j

129: end

18: - The SP2 certificate proof is the standard exp/log monotonicity argument (exp is strictly increasing,
19:   `exp (a + log ε) = ε · exp a` for `ε > 0`), plus the triangle bound `|bulk − exact| ≤ e_q` applied twice, once at
20:   the skipped key and once at the prefix argmax. The derivation of δ = ln(1/ε) + 2·e_q is SP2's (primer §4.3, [R06]);
21:   BLASST's ln λ threshold is the same quantity without the 2·e_q margin.
22: - The numeric bounds `exp 1 > 2.7182818283`, `exp 2 > 7`, `exp 6 ≥ 7`, `exp 10 > 49 · exp 2` use Mathlib's
23:   `Real.exp_one_gt_d9` (`Mathlib/Analysis/Complex/ExponentialBounds.lean`) and `Real.add_one_le_exp`
24:   (`Mathlib/Analysis/Complex/Exponential.lean`); the SP2 witness uses `Real.log_le_sub_one_of_pos`
25:   (`log x ≤ x − 1`). Standard bounds; no prior art beyond Mathlib is claimed for their use here.
26: - The z-score counterexample rows are the lead's / SP1's (primer §4.1, [R24]); the proof is direct evaluation.

39: /-- Every key at or before `j` is at most the prefix maximum at `j`. -/
40: theorem le_prefixMax {n : ℕ} (b : Fin (n+1) → ℝ) {i j : Fin (n+1)} (hij : i ≤ j) :
41:     b i ≤ prefixMax b j := by
42:   unfold prefixMax
43:   exact Finset.le_sup' b (by simp [hij])
44: 
45: /-- The prefix maximum at `j` is at most any common upper bound of keys `0..j`. -/
46: theorem prefixMax_le {n : ℕ} (b : Fin (n+1) → ℝ) (j : Fin (n+1)) {c : ℝ}
47:     (h : ∀ i, i ≤ j → b i ≤ c) : prefixMax b j ≤ c := by
48:   unfold prefixMax
49:   exact Finset.sup'_le _ _ (fun i hi => h i (by simpa using hi))
50: 
51: /-- The running maximum never decreases (the monotonicity behind the SP rule; BLASST's running max). -/
52: theorem prefixMax_mono {n : ℕ} (b : Fin (n+1) → ℝ) {j k : Fin (n+1)} (hjk : j ≤ k) :
53:     prefixMax b j ≤ prefixMax b k :=
54:   prefixMax_le b j (fun _ hi => le_prefixMax b (hi.trans hjk))
55: 
56: /-- Every key is at most the row maximum. -/
57: theorem le_rowMax {n : ℕ} (b : Fin (n+1) → ℝ) (i : Fin (n+1)) : b i ≤ rowMax b := by
58:   unfold rowMax
59:   exact Finset.le_sup' b (Finset.mem_univ i)
60: 
61: /-- A prefix maximum is at most the final (row) maximum. -/
62: theorem prefixMax_le_rowMax {n : ℕ} (b : Fin (n+1) → ℝ) (j : Fin (n+1)) :
63:     prefixMax b j ≤ rowMax b :=
64:   prefixMax_le b j (fun i _ => le_rowMax b i)

66: /-- The prefix maximum is attained at some key `m ≤ j`. -/
67: theorem exists_prefixMax_eq {n : ℕ} (b : Fin (n+1) → ℝ) (j : Fin (n+1)) :
68:     ∃ m, m ≤ j ∧ prefixMax b j = b m := by
69:   unfold prefixMax

38: ## 1. What APA is
39: 
40: ### 1.1 Plain language
41: 
42: In attention, `softmax(q·kᵀ/√d)` is exponential. A few keys near the top score take nearly all the weight, and most keys
43: end up multiplied by almost zero. APA's bet is that those near-zero keys do not need a precise score. They need **a**
44: score, so they stay in the denominator, but a cheap one will do. The keys that carry the weight get the exact dot
45: product [R10, R11].
46: 
47: ### 1.2 Precisely: the data path (quoted from the kernels)
48: 
49: For one query row `q`, with keys `k_j`, low-precision keys `k̂_j` ("kq"), values `v_j`, and scale `1/√D`:
50: 
51: 1. **Bulk score, every eligible key:** `bulk_j = (q · k̂_j) · scale`. `k̂_j` is the key after TurboQuant-style
52:    quantisation: per-head rotation plus a Lloyd–Max codebook at 2 or 4 bits (the fused INT4/INT8 paths are separate
53:    variants). In the evaluated `apa_selective` and SP kernels, `k̂` is **dequantised back into the key dtype (fp32 in the
54:    SP measurements)**. It is not packed low-bit storage [R12]. So the "low precision" is in the *values* of `k̂`, not in
55:    the arithmetic width of the kernel. The INT4-internal fused kernel from APAMQ is the exception: it reads packed INT4
56:    [R21].
57: 2. **Selection.** Two rules exist (§3, §4).
58: 3. **Refine:** for selected keys, `score_j = (q · k_j) · scale` against the full-precision key. Unselected keys keep
59:    `score_j = bulk_j`.
60: 4. **Exact online softmax over all keys** with full-precision `V`. An optional learned sink logit is folded into the
61:    denominator once [R04, R10].
62: 
63: The original **two-pass** rule, verbatim from `tensor_cuda/src/kernels.cu` (`apa_selective_kernel`) [R01, R02]:
64: 
65: ```cuda
66: // Pass 1: bulk scores -> sum/sumsq of |bulk| for the z-score threshold.
67:       float a = fabsf(dot * scale);
68:       sum += a; sumsq += a * a;
69:   ...
70:   float thr = mean + zthr * sqrtf(fmaxf(var, 0.f));          // kernels.cu:1225
71:   // Pass 2: SINGLE pass with an online softmax (FlashAttention-style).
72:       if (fabsf(bulk) >= thr) {                                // kernels.cu:1252
73:         ... ex = q · k_j ...; score = ex * scale;
74:       } else { score = bulk; }
75: ```
76: 
77: `zthr = Φ⁻¹(1 − refine)`, computed host-side in `quant.py:176` [R03]. The **single-pass** rule, verbatim from
78: `apa_selective_sp_kernel` [R04]:
79: 
80: ```cuda
81:     const float bulk = __shfl_sync(FULL, dot, 0) * scale;
82:     bulk_max = fmaxf(bulk_max, bulk);
83:     const bool refine = bulk >= bulk_max - delta;            // kernels.cu:7896
84: ```
85: 
86: The split-K decode variant uses a partition-local inclusive prefix instead: `refine = valid && bulk >= prefix - delta`
87: (`apa_sp1_1.cuh:73`) [R05].
88: 
89: ### 1.3 "One-sided" and "never over-claim": what the blend does and does not promise
90: 
91: *The order uses these phrases. I did not find either one verbatim in the sources (see §8, RED). What follows is the
92: sourced content they most plausibly refer to.*
93: 
94: - **The two rules differ in which side they look at.** The z-score rule thresholds `|bulk|`, so it refines strongly
95:   **negative** scores as well as strongly positive ones [R01, R02]. The running-max rule is **signed and one-sided**. It
96:   refines only keys whose bulk score is within δ of the running maximum, and a large negative score is never refined
97:   [R04]. SP3 measured the consequence: the z-score rule "selects |bulk| size, not softmax weight". It leaves 92% of the
98:   softmax mass on unrefined keys, while the running-max tail leaves 13% (model perplexity study, MiniCPM3-4B) [R29].
99: - **The single pass errs in one direction only.** The running maximum never decreases, so a key skipped at step j would
100:   also be skipped against any later or final maximum. A key refined early may prove unnecessary, which "costs work but
101:   never correctness" relative to the final-max rule (proof + 40,000-draw unit test) [R24]. The kernel comment says the
102:   same: "A skipped key stays below final_bulk_max-delta; an early refinement may be conservative" [R04]. The Hunyuan3D
103:   run showed the same direction for the z-score quantile rule: its off-nominal blocks over-refined (0.23–0.24 versus
104:   0.15), "never under" (E2E visual) [R36].
105: - **What the blend does *not* promise:**
106:   - The paper says the output deviation is "bounded by the bulk-quantization error on the un-refined set" [R11]. SP2
107:     made that bound exact: `δ = ln(1/ε) + 2·e_q` [R06]. On real 2- and 4-bit keys it is **vacuous**. It refines
108:     ≥ 99.6% of keys at 2 bits, and 69–100% at 4 bits [R27].
109:   - The paper argues the skipped weight "was … already going to be near zero" [R11]. SP3 found the z-score tail
110:     skipping a key with relative weight 1.0 on **every** layer [R29].
111:   - Under split-K, extra refinements change the output, so partitioned output is **not** equal to global-prefix output.
112:     SP1.1 disproved that equality with an explicit counterexample [R26].
113:   - Operationally, "never over-claim" is the house rule: no model-quality claim from a kernel sweep [R47].
